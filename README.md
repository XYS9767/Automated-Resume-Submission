# BOSS 自动投递 · 优化版

修复在线简历读取、自动搜索翻页、岗位匹配、真实沟通确认、招呼语送达检查和中断续跑。已完成规则与本地浏览器回归测试，已完成实网小批次验证。详见 [检查与修复说明](检查与修复说明.md)。

这版重做了搜索、岗位核对、投递确认和断点续跑。默认读取配置连续运行；扫码登录和网站验证码由本人完成，完成后自动继续。

## Windows 发布包

在 [Releases](https://github.com/XYS9767/Automated-Resume-Submission/releases) 下载 Windows x64 ZIP，完整解压，双击包内的 **启动.bat**。需要 Microsoft Edge，无需安装 Python。包内同时提供预览、环境检查和停止入口。发布包使用通用招呼语，可在 `config.yaml` 修改。

发布包不包含账号登录状态、Cookie、个人简历或历史投递记录。一个运行目录对应一个账号；换账号时另解压一份。

## 源码运行

1. 当前配置为 `resume.source: boss_online`，启动时读取已登录账号的在线简历，不需要选择本地文件。
2. `search.source: config` 按配置中的城市、关键词和薪资筛选，当前为深圳、运维/DevOps、15-20K；不会被在线简历中的其他城市期望覆盖。岗位标注的最低月薪须在 15-20K 内：10-20K、12-18K、薪资面议均跳过，15-20K、15-25K 可以继续匹配（岗位最高薪资不是投递底线）。设为 `boss_online` 则沿用在线期望（未配置此项的旧配置仍沿用在线期望）。筛选门槛与招呼语在 `config.yaml` 修改。
3. 双击 **启动.bat**。首次环境未安装时会自动安装依赖；随后在专用 Edge 窗口登录。
4. 如需先检查岗位，双击 **预览岗位.bat**。预览会保存匹配结果，不点击沟通。
5. 双击 **停止自动投递.bat** 请求停止，当前操作完成后保存进度；再次双击启动可续跑。停止请求也会保留到命令行启动，命令行续跑前需删除项目内的 `stop_requested.flag`。

运行需要 Python 3.10+ 和 Microsoft Edge。启动时优先复用依赖完整的项目虚拟环境，其次尝试本机 `py -3` / `python`；都不可用时才创建项目虚拟环境并安装依赖。中断安装产生的不完整虚拟环境不会阻止复用本机可用环境。

安装入口优先使用 Windows 的 `py -3`，没有启动器时使用 `python`。已安装依赖时也可用 `py -3 main.py --search-only` 预览。如需单次试投，在自己的配置副本中设置 `submit.max_attempts_per_run: 1`（失败或结果待核实也计入点击额度），再通过 `--config` 指定。正式配置保留每日上限150。

2026-10-28 修正：登录后残留的 `_security_check` 参数不再被单独判为验证码；真实验证路由和可见控件仍会暂停。数字经验上限如 `2年`、`5年` 按实际值处理；不带单位的薪资如 `10-20` 会明确报错，避免筛选悄悄失效。可用 `py -3 -B -m unittest discover -s tests -v` 运行本次回归测试。

要切换为本地简历，设置 `resume.source: local`，将自己的 PDF/DOCX/TXT 放入 `resumes`，并填写搜索城市和关键词。在线模式读取失败时会明确报错，不会偷偷切换到目录中的其他人简历。

其他入口：

- `检查环境.bat`：检查配置、依赖、浏览器和简历位置。
- `python main.py --interactive`：恢复关键词编辑和筛选菜单。
- `python main.py --resume 自己的简历.pdf --resume-only`：仅验证简历解析。
- `python main.py --config my_config.yaml`：指定配置。

专用窗口默认沿用系统网络；排查网络问题时可设置 `browser.proxy_mode: direct`，只影响专用浏览器。修改后需重开该专用窗口才能生效。

配置中的相对文件路径以项目目录为基准。通过 BAT 启动时会自动切换到该目录。

## 已修复的主要问题

| 原来的问题 | 本版处理 |
| --- | --- |
| 浏览器启动后搜索反复校验 | 使用明确回环调试端口，保存并核对专用浏览器身份；本机登录保留后搜索恢复 |
| 搜索之后才监听，第一页丢失 | 先监听再导航，持续接收网页自己的响应 |
| 校验回首页后要求手动搜索 | 网站状态稳定后由程序重新搜索配置关键词和城市，最多恢复重搜 1 次 |
| 页面跳转后响应变成空内容 | 启用持久响应缓存，区分捕获失败、网站拒绝与零岗位 |
| 得到第一页就不再翻页 | 按配置翻页，识别下一页按钮、滚动容器和 hasMore |
| 推荐数据、旧关键词、其他城市混入 | 核对请求关键词与城市；DOM 回退也核对搜索框 |
| 标签命中就可能投错岗位 | 关键词去掉“实习/开发”等泛词，支持技术别名，详细 JD 优先于标签 |
| 同标题、同前缀的岗位被误认成同一个详情 | 使用完整岗位 ID，不再按前八个字点击 |
| 缺少 AI Key 也逐岗重试 | 识别空值/占位密钥；认证错误停用 AI，超时暂时回退本地规则 |
| 规则固定给嵌入式方向加分 | 按每份简历自己的技能匹配；新增 RAG、LLM、LangGraph 等识别 |
| 真正的沟通按钮存在，文字定位却找不到 | 定位按钮元素后校验标准化文字、可见性和禁用状态 |
| 学历和工龄标签当成技能，详情技能未纳入 | 排除非技能标签，合并 JD 要求，并检查标题明确的核心技术栈 |
| 点击就算成功，失败仍增加次数 | 接收当前岗位的沟通响应，或确认同一岗位按钮变为“继续沟通” |
| 中断后重投、追踪参数变了就失去去重 | 按岗位 ID 去重；保存待办队列和每次点击状态 |
| 频繁回车、爱企查阻塞、关闭用户所有 Edge | 默认无终端确认；公司检索可选；专用浏览器保留登录 |

当前官网职位入口为 `/web/geek/jobs`，可通过 `search.path` 调整；不能按旧日志断定复数路由错误。[BOSS 官网职位入口](https://www.zhipin.com/web/geek/jobs)

网络监听顺序与 `wait()` 返回值按 DrissionPage 4.1.1.4 文档实现，并固定了该版本。[DrissionPage 网络监听文档](https://www.drissionpage.cn/browser_control/listener/)

## 配置变化

当前发布默认每个关键词搜索10页、规则最低分75、BOSS今日活跃；岗位起薪须落在15-20K内。筛选条件可在 `config.yaml` 调整，历史配置保存在 `config.original.yaml`。

`search.experience` 是网站列表的精确档位筛选；`filter.max_experience` 是可接受的经验上限。本版默认前者留空；在线模式按简历明确填写的工作年限设置后者，无需填写固定年限。当前默认仅选择全职岗位，因此过滤实习、在校及兼职。区间经验按最低要求比较，例如 3–5 年岗位最低要求是 3 年。

月薪区间不会直接套到“元/天”的实习工资上。若只要实习，可以设置：

```yaml
filter:
  job_type: internship
```

不认识的城市可以补充 `search.city_code`。如要跳过缺少 JD 的岗位，可设置 `filter.require_description: true`；未知 BOSS 活跃度默认放行，可用 `filter.unknown_boss_activity: skip` 改为跳过。

## AI 与公司检查

`risk_check.api.token` 留空时使用本地规则。需要 AI 匹配时，配置有效的 DeepSeek Key，或设置环境变量 `DEEPSEEK_API_KEY`。模型和兼容 API 地址可用 `model`、`base_url` 配置。

AI 只对选中的一份完整简历评分，避免拼接多份简历造成虚假匹配。选中的文件名写入记录；它不会因此自动上传到网站。

默认关闭爱企查浏览器检索，可用 `risk_check.company_lookup: true` 开启。没有获取到实际企业资料时使用本地风险规则；本版不把凭公司名推断标为“已联网查证”。

## 中断、记录与结果含义

- `apply_record.json` / `submit_log.csv`：处理结果、跳过原因、匹配分、简历文件和来源关键词。
- `pending_jobs.json`：未完成岗位队列；下次运行先合并已有待办。
- `submission_state.json`：确认成功、已沟通和待核实的岗位状态，以及每日计数。
- `daily_count.json`：兼容旧版的每日计数。
- `last_run_summary.json`：本轮分类统计。
- `runtime.log`：运行和异常日志；单文件约 5 MB，轮换保留。
- `capture_log.txt`：每个关键词捕获的岗位清单。

**记录中的“投递成功”兼容旧版名称，表示确认发起了沟通，不表示本地简历附件已发送。** 自定义招呼语只有在聊天窗口与岗位身份可确认时才尝试发送，其结果单独记录。本版不会自动上传/发送本地附件。

如果点击后断线、没有得到可核实结果，该岗位会标为“待核实”，不会盲目重发。请先在 BOSS 沟通记录中核对，再将 `submission_state.json` 对应岗位状态改为 `already_applied`（确已沟通），或在确认未发送后删除该岗位条目以允许重试。修改前先退出程序并备份文件。

按 Ctrl+C 可停止。一般单岗异常保留待办并继续其他岗位；连续多次失败先等待并重建详情标签，恢复多次仍失败会保存队列后退出。网站自动校验时等待恢复；实际出现登录/验证码交互才提示完成该项，之后程序自动重搜，无须手动搜索。连续校验失败会保存进度和明确错误原因后退出；平台次数上限不会被提高或绕过。

已验证自动搜索、逐岗匹配、真实沟通及招呼语送达；发布前运行完整回归及 EXE 解压启动检查。默认本地每日上限为 150；实际数量取决于匹配结果和网站返回，以本机 `daily_count.json` 和网站沟通记录为准。首次扫码与网站要求的验证码仍由账号本人完成。
